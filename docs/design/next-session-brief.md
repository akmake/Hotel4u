# הוראות לצ'אט הבא — העברת כל מסכי ה־PMS לשפת העיצוב החדשה (2026-10-28)

אתה ממשיך עבודה על hotel4u (מערכת ניהול מלון, React + Vite ב־`client/`, Node + Express + MongoDB ב־`server/`).
יוסף (בעל המוצר) הולך לישון. המשימה: לעבור **מסך אחרי מסך** על כל מסכי `/pms/*` שעוד לא עברו לשפה החדשה, ולסדר כל אחד בקו העיצובי שכבר אושר — עד הסוף, בלי לעצור לשאלות. בבוקר הוא יעבור על הכל בעין.

ענה תמיד בעברית. דיווחים קצרים.

---

## 3. השפה העיצובית המאושרת — מפרט מדויק
מקורות אמת שכבר בנויים ומאושרים (תעתיק מהם, אל תמציא):
- `client/src/pages/TodayPage.css` — דף "היום" (`/pms`).
- `client/src/pages/inv/RoomChartPage.jsx` + `.css` — לוח חדרים (`/pms/tape-chart`).
- `client/src/pages/rsv/ReservationPage.jsx` + `.css` — תיק הזמנה.
- `client/src/pages/inv/AvailabilityPage.css` (שכבת `.avl-page` בסוף הקובץ) — לוח זמינות.
- `client/src/components/frontdesk/CheckInWizard.css` (וריאציה `accordion`), `AssignRoomStudio.css` (וריאציה `today`).

**ערכים:**
- רקע עמוד: אפור ניטרלי `color-mix(in srgb, #808080 12%, white)` — דרך `.page-content:has(> .X-page) { background: … }`.
- כרטיסים: לבן `#fff`, פינות `12px`, **בלי צל במנוחה**, בלי מסגרת. קווי הפרדה פנימיים: `rgb(var(--fg) / .08)`.
- גופן: Heebo בכל מקום (לא Rubik, לא Roboto). כותרת עמוד 20–22px/600, כותרת כרטיס 15px/600, טקסט 14px, משני 12–13px אפור (`--fg-muted`). מספרים: `font-variant-numeric: tabular-nums`.
- טורקיז `#006a61` **רק** לפעולה ראשית, בחירה ו"היום". לא לרקעים.
- כפתורים — Material 3:
  - ראשי: גלולה 40px, רקע `#006a61`, טקסט לבן, hover עם צל קל.
  - משני: גלולה 40px, מסגרת `1px #6f7977`, טקסט טורקיז.
  - טקסט: בלי מסגרת, טקסט טורקיז. אייקון: עיגול 40px.
  - כפתור מקוטע (segmented): גלולה עם מסגרת, הנבחר `#cce8e3` / טקסט `#324b47`.
  - כפתור מפוצל (פעולה + חץ לתפריט) — ראה `SplitAction` ב־`DailyWorkspace.jsx`.
- צבעי מצב: ירוק `rgb(21 128 61)` (בבית/מוכן), טורקיז רך `#cce8e3` (מאושר), כתום `#ffddb8` / `#653e00` (ממתין/דורש טיפול), אפור (עזב/עבר), אדום `rgb(185 28 28)` (חסום/חוב).

**מבנה עמוד קבוע:**
1. **שורת כותרת אחת** (לא שתיים!), עם קו מפריד מתחתיה:
   מימין — כפתור חץ חזרה (אייקון בלבד, `ArrowRight`, עיגול 40px) + כותרת + מידע משני קטן ליד. משמאל — הכלים מקובצים, ובקצה הפעולה הראשית.
   החזרה: `if ((window.history.state?.idx || 0) > 0) navigate(-1); else navigate('<דף-אב>')` — חוזר למקום שממנו הגיעו.
2. שוליים מהקצוות (המסך לא צמוד לקצוות). ב־`FLUSH_ROUTES` ב־`AppShell.jsx` הדף צריך ריפוד משלו (`22px 28px`).
3. רשימות: כל שורה ככרטיס לבן נפרד עם רווח קטן, מתחת לשורת כותרות עמודות אחת — לא טבלה עם רשת. כותרות עמודות צמודות (מרווח מינימלי מהשורה הראשונה).
4. מקרא — בשורה שקטה מתחת לתוכן, לא בכותרת.
5. פאנל צד/פרטים — מופיע רק כשבחרו משהו; אחרת התוכן ברוחב מלא.
6. פעולות — גלויות על הדף עם הסבר קצר לכל אחת (וכשלא זמינה — למה). לא להחביא בתפריט "⋯". פעולה ראשית אחת בולטת.
7. צ'ק-אין / צ'ק-אאוט / שיבוץ — נפתחים במקום (חלון), לא שולחים למסך אחר.

**טכנית:** לכל מסך — קובץ CSS משלו עם מחלקת עטיפה (`.X-page`), עיצוב בתוך הסקופ בלבד. מומלץ בצעד ראשון לחלץ את המשותף (כותרת, כפתורים, כרטיסים, מקוטע) לקובץ אחד משותף (למשל `client/src/components/kit/approved.css`) ולהשתמש בו בכל המסכים, במקום להעתיק.

## 4. מה יוסף אוהב / לא סובל (חשוב מאוד)
**אוהב:**
- מסך ההגדרות של Windows 11: הבדל ברור בין כרטיס לרקע, הכל מיושר, נקי.
- רקע אפור + כרטיסים לבנים. כפתורי Material.
- צפוף ומקצועי, שורה עליונה אחת, הכל במקום הנכון.
- שהמשתמש מבין מיד מה כל דבר אומר — בשפה פשוטה, בלי ז'רגון של המערכת.
- מידע אמיתי ושימושי במבט אחד (שורת סיכום), פעולות גלויות.
- חזרה חכמה למקום הקודם.

**לא סובל:**
- עיצוב שנראה "AI" / גנרי, וריאציות שאלתרת מהראש.
- רקע תכלת/מנטה/צבעוני, או רקע כמעט לבן בלי הבדל מהכרטיסים.
- דברים מגושמים: מספרים ענקיים, כפתורים כבדים, צבעים כהים מדי.
- תווית קטנה מעל כותרת ("eyebrow"), כותרות שיווקיות ("כל הפרטים, ביום שתבחרו.").
- כפילות מידע (אותו דבר מופיע פעמיים-שלוש), מקרא של 8 פריטים, טקסטי הסבר שמדביקים במקום לתקן.
- להציג את "המודל של המחשב" (למשל "2 הזמנות בלי חדר בלילה") במקום את מה שהמשתמש חושב ("לכהן אין חדר").
- כפתורים ששולחים למסכים אחרים, פעולות מוחבאות בתפריט.
- טבלאות עם רשת כבדה, שתי שורות כותרת, תוכן צמוד לקצוות, דברים נחתכים.
- "עשיתי את המסביב" — לשנות רק מסגרת ולהשאיר את הליבה כמו שהיא. **צריך לבנות מחדש את הליבה של כל מסך.**
- נתונים מזויפים, כפתורים שלא עובדים.

## 7. שיטת עבודה לכל מסך
1. קרא את קובץ המסך. מפה: איזה מידע יש, אילו פעולות/כפתורים, לאן כל כפתור שולח, מה כפול.
2. החלט מה העיקר של המסך למשתמש (פקיד קבלה / מנהל) ומה מיותר.
3. בנה מחדש: שורת כותרת אחת + חזרה, שורת סיכום אם רלוונטי, תוכן ככרטיסים/שורות־כרטיס, פעולות גלויות, פאנל רק בבחירה.
4. **אסור לשנות לוגיקה עסקית, API, הרשאות או חישובים.** רק מבנה תצוגה ועיצוב. כל הכפתורים חייבים להמשיך לעבוד.
5. build + detector. אם נכשל — לתקן לפני שעוברים מסך.
6. רשום שורה ב־`docs/design/next-session-log.md`: מסך, מה השתנה, מה לא נבדק.
