## הרכב אורחים בהזמנה מרובת חדרים

נוספו שדות אופציונליים להרכב ביחידת שהייה, ללא ברירת מחדל שממציאה אפס אורחים. כאשר הם ידועים, נבדקת קיבולת ביחס ליחידה המסוימת.

בהזמנות ישנות ללא חלוקה ידועה לא מניחים חלוקה שווה. אם חדר היעד יכול להכיל את כל הרכב ההזמנה אפשר להוכיח שאין חריגה גם בלי החלוקה. אחרת המעבר נחסם בהודעה שצריך להשלים את הרכב היחידה. מסך להזנת חלוקת הרכב מלאה לא נבנה בתיקון הזה; אין כאן טענה ש־ARR03 הושלם.

## גבולות התיקון

- מעבר חדר דורש MongoDB עם תמיכה בעסקאות, כגון Replica Set. בסביבה ללא תמיכה מתקבלת הודעת אי־זמינות; אין ניסיון לבצע שמירות נפרדות כחלופה. לא אומתה תצורת מסד הייצור ולא שונתה כאן.
- נוספה רשומת בקשות מעבר עם אינדקס ייחודי לפי נכס, הזמנה ומזהה בקשה. רשימת האינדקסים נבנית לפני מעבר; אין צורך בשינוי רשומות קיימות.
- חלון המעבר שולח מזהה בקשה קבוע במהלך ניסיון הפעולה. קריאות ישנות ללא מזהה נשארות נתמכות, אך אינן מקבלות זיהוי ניסיון חוזר. צרכן API נוסף צריך לשלוח `requestKey` כדי לקבל את ההבטחה הזאת.
- תיקון הבעלות חל על שחרור נעילות משותף. ההגנה מפני כתיבה של בקשה שפג תוקפה שולבה ונבדקה במעבר חדר; אין טענה שכל תהליך אחר המשתמש בנעילות עבר הסבה לעסקאות או בדיקת עומס.
- התיקון אינו מבצע החלפה ייעודית בין שני שוהים, אינו מחבר ספק מפתחות ואינו מחבר סליקה. אלה פערים נפרדים שנשארו פתוחים.
- לא בוצעה הרצה דרך דפדפן או משמרת אמיתית במלון. בדיקת הלקוח היא בנייה; בדיקות השרת הן שירותים ונתיבי API בסביבה מבודדת.
- אין תיקון אוטומטי לנתונים היסטוריים שכבר נפגעו. הבדיקות המקוריות יצרו פגיעה רק בבסיס זמני; לא נבדק אם קיימים נתונים פגועים בשרת פעיל.

## הרצה חוזרת

משורש הפרויקט:

```text
npm --prefix server run qa:readiness:room-moves
npm --prefix server run qa:stay:isolated
npm --prefix server run qa:fiscal:unit
npm run build
```

שתי חבילות בדיקת השהייה משתמשות בבסיס מקומי זמני. רגרסיית השהייה משתמשת בנתיבים ובאימות העובד האמיתיים, ללא הפעלת האפליקציה המלאה, מתזמנים או טעינת `.env`. תוצאות בדיקות אינן אישור משפטי למדיניות ביטול או לתמחור; הן בודקות את התנהגות הקוד המוגדרת.
