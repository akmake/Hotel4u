# ADR-ACCOUNTING-001 — גבולות המנוע החשבונאי

מצב: החלטות הנדסיות בתהליך מימוש. אישורי דין ושחרור אינם כלולים. 18.10.2026.

## זהות וגבולות גישה

Property הוא תחום גישה תפעולי; LegalEntity היא זהות בעל הספרים. ההגדרה הראשונית יוצרת שיוך מפורש לנכס ולפרופיל מנפיק גרסאי, בלי למזג נכסים אוטומטית לפי מספר עוסק. TenantKey נגזר מנכס מורשה; אינו מתקבל מלקוח API. איחוד ישות בין נכסים דורש מיפוי מיגרציה נפרד ובדיקת הרשאות לרשת. API מחזיר פקודות ודוחות של הנכס המורשה בלבד. נעילת תקופה משותפת ליותר מנכס אחד מחייבת הרשאת מנהל רשת.

## כסף ועיגול

`domain/money.js` מפרש מספר עשרוני למונה ומכנה מסוג BigInt. כסף בספר החדש נשמר כמחרוזת עשרונית קנונית בשתי ספרות; הכפל בכמות, ההנחה והמס נעשים בחישוב מדויק. מעגלים לכל שורה בשיטת HALF_AWAY_FROM_ZERO, מחשבים מס כהפרש בין נטו לברוטו במחיר כולל מס, ושומרים מזהה מדיניות. ההמרה ל־Number מוגבלת לגבול התאימות של Invoice הקיים, עם בדיקת טווח. Folio הישן עדיין דורש מיגרציית כסף מלאה; אין להצהיר שכל המערכת הוסבה.

## טרנזקציות וסדר פעולות

מסמכי Folio, חשבוניות ידניות וזיכויים נכתבים עם המונה, Audit מחייב ואירוע Outbox באותה טרנזקציה, snapshot read + majority write. אין fallback לכתיבה ב־standalone. פעולות רשת מתבצעות לאחר commit. בקשת מסמך Folio שומרת payload hash ומחזירה 409 אם אותו מפתח חוזר עם תוכן שונה. המונה המשותף גורם לתחרות על אותו Property; מנהל ההתקן חוזר על טרנזקציה במקרי write conflict. נדרשות ראיות מול Replica Set לפני שחרור.

סדרת LegalEntity נפרדת מהסדרה הישנה. יצירת סדרה מכינה אותה אך אינה מפעילה אותה. חיבור המספור החדש להנפקה מחייב החלטת DEC-01 ותוכנית cutover; אסור להחליף סדרה היסטורית בשקט.

## אי־שינוי וביקורת

Invoice חוסם שינוי תוכן ב־save וב־Query, החלפה ו־bulkWrite. מידע תפעולי להקצאה, הדפסה וקישורי זיכוי ניתן לעדכון ברשימת שדות סגורה. מסמך סופי אינו יורד למצב draft ואינו נמחק דרך המודל. JournalEntry, AccountingEvent, PaymentEvent, TaxRule, IssuerProfile ו־DocumentArtifact מקבלים hooks לפני הידור המודל ונחסמים לעדכון/מחיקה. גישה ישירה דרך MongoDB driver עוקפת Mongoose: יש להגדיר משתמש DB עם find/insert בלבד לאוספים הבלתי משתנים ולהפריד הרשאות תחזוקה. בדיקת הרשאות DB היא שער שחרור, לא הוכחה שמסופקת על ידי hooks.

Audit פיסקלי מחייב הצלחה ונשמר בטרנזקציה. פרופילי מנפיק וכללי מס מתעדכנים באמצעות גרסה חדשה. מרשם החלטות ציות שומר גם את פעולת השינוי ביומן, בעל סמכות, מקור, גרסה, אסמכתה, תחולה ומועד בדיקה מחדש.

## זיכויים

שורת זיכוי מצביעה לשורת החשבונית המקורית. היתרה לכל שורה מחושבת מתוך הזיכויים הקודמים. סכום כללי מחולק בשיטת השארית הגדולה; זיכוי נבחר מתייחס רק לשורה שנבחרה. העיגול שומר על סכום המס המקורי בכל זיכוי ובזיכוי היתרה. הכתיבה לקישור creditedBy במקור משתתפת בטרנזקציה ומכריחה טיפול בתחרות בין זיכויים. היסטוריית זיכויים ללא קישורי שורה נחסמת לבדיקה מקצועית ולא משויכת בניחוש.

## ספר ראשי

פקודה מחייבת שתי שורות לפחות, חובה=זכות, חשבונות פעילים של אותה ישות ותקופה פתוחה. כתיבת version בתקופה מונעת תחרות שקטה בין רישום לסגירה. מקור אירוע ייחודי מונע פקודה כפולה; hash מונע שימוש חוזר עם תוכן שונה. היפוך משתמש במפתח מקור דטרמיניסטי. אין רישום הכנסה אוטומטי מהנפקת מסמך: Accounting Events ממתינים למיפוי פקודות מאושר בידי רו״ח. הסביבה החדשה נשארת shadow ולא מחליפה ספרים קיימים.

## תשלומים

AccountingPaymentService מגדיר חוזה ספק capture/query/refund/queryRefund. כוונת תשלום ומזהה פעולה נשמרים לפני קריאת ספק. אחרי timeout המצב unknown; המשך אפשרי רק בבירור. החזר שומר הזמנה של יתרת ההחזר בטרנזקציה, כולל החזרים pending/unknown, ומשחרר אותה רק בסירוב סופי. אירועי ספק כפולים מזוהים על פי ישות+ספק+מזהה אירוע; אירוע authorization מאוחר אינו מחזיר captured אחורה. אין ספק חי רשום כברירת מחדל; verifyWebhook וחתימה חייבים להימצא ב־adapter של הספק לפני חיבור API ציבורי.

## ארכיון ושחזור

Outbox עם lease token, ניסיונות חוזרים ומצב failed לאחר מיצוי. תהליך פנימי יוצר עותק JSON קנוני של תוכן המסמך, SHA-256 וגרסת פורמט. זהו ארכיון נתונים בלתי משתנה, **לא PDF חתום ולא מסמך ממוחשב מאושר**. המערכת אינה מסמנת signed ללא ספק חתימה. הורדת הארכיון מאמתת hash והרשאת נכס. עד החלטת מדיניות שמירה אין מחיקה אוטומטית ו־legalHold מופעל.

## מיגרציה וחזרה

`accountingInventory.mjs` הוא read-only ונטען רק עם MONGO_MIGRATION_URI מפורש; אינו טוען .env של היישום. מציע קבוצות לבדיקה, מאתר מספרים חריגים וכפילויות, ואינו משכתב מסמכים. לא נבנה מסלול apply לפני אישור המיפוי. לפני פריסה: גיבוי עקבי, בדיקת Replica Set, הגדרת הרשאות/indexes, inventory וסגירת החלטות. חזרה לגרסת יישום קודמת אינה מוחקת אירועים וספרים חדשים; יש להשבית הנפקה בזמן הבירור, ולתקן פעילות אמת באסמכתאות.
