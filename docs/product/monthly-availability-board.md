# לוח זמינות חודשי — מחקר ואפיון

תאריך: 2026-10-26 · סטטוס: נבנה כלוח שנה חודשי (`/pms/availability`): כרטיס לכל יום עם נתונים מהירים, ולחיצה / גרירה על ימים פותחת פאנל פרטים. השלבים הבאים נכנסים לכרטיס היום ולפאנל.
המטרה: מסך שבו איש הזמנות / מנהל רואה חודש קלנדרי שלם ויודע לכל לילה **כמה אפשר עוד למכור, למי כבר מכרנו, ובכמה**.

## 1. מה עושות המערכות המובילות

### Oracle OPERA (Property Availability) — הסטנדרט בתעשייה
מסך זמינות בחלוקה ל"בית" (כל המלון) ולסוגי חדרים, תצוגת שבוע / חודש. המשתמש בוחר אילו שורות להציג ("View Options"):

| שורה | משמעות |
|---|---|
| פנויים למכירה (Max Available) | חדרים פיזיים − חסומים − נמכרו ± מגבלת מכירה (אוברבוקינג) |
| פנויים כולל אופציות | כנ"ל, פחות הזמנות לא-סופיות (non-deduct = טנטטיב) |
| נמכרו (סופי) / נמכרו (אופציה) | הפרדה בין הזמנה מחייבת להזמנה על תנאי |
| בוטלו | הזמנות שבוטלו להגעה באותו יום |
| תפוסה % / תפוסה כולל אופציות % | נמכרו ÷ (פיזיים − חסומים + מגבלה) |
| זמינות % | ההפך |
| חדרים פיזיים, לא תקין (OOO), מחוץ לשירות (OOS) | |
| הגבלות | דגל: יש סגירה / מינימום לילות / סגור להגעה בתאריך |
| קבוצות: הוקצו / נוצלו (מחייבות ולא מחייבות) | |
| חדרים מגיעים / עוזבים, אנשים מגיעים / עוזבים | |
| אנשים בשהייה | |
| שימוש יומי (Day use) | |
| מגבלת מכירה (Sell limit) | חיובי = אוברבוקינג מותר, שלילי = שמירת חדרים |

פעולות מהלוח: לחיצה על **תאריך** → ניהול הגבלות; על **פנויים** → מגבלת מכירה; על **תפוסה** של סוג → רשימת השוהים; על **מגיעים** → רשימת המגיעים; "פרטי קבוצה" → ניהול חדרי קבוצות. ריחוף על תא → פירוט. קו צבעוני מסמן שקיימת מגבלת מכירה.

### Mews (Availability & occupancy)
שלוש לשוניות על אותו טווח: **סקירה** (תפוסים, פנויים, חדרים פנויים פיזית, מחיר ממוצע, הזמנות מאושרות / אופציה, קבוצות מאושרות + אחוז ניצול, קבוצות אופציה, בירורים, OOO, שימוש פנימי, מגיעים, עוזבים, ממשיכים, אורחים), **תפוסה** (אחוז לכל סוג + מחיר, הצללה כהה = מלא, אדום = אוברבוק), **זמינות** (פנויים / סה"כ / תיקון ידני / מחיר ממוצע, לחיצה על תא = תיקון). מסננים: חברה, סוכן, סוג חדר, תעריף, מאושר / אופציה.

### Cloudbeds / HotelRunner / Odoo / ResortData
- קבוצה מוצגת כשבר "6/20" (נוצלו / הוקצו) עם מסגרת מקווקוות. תפוסה סופרת הקצאות מחייבות כנמכרות.
- קוד צבעים לתפוסה: ירוק פנוי, כתום מעל חצי, אדום מלא; "מלא" שונה מ"סגור למכירה".
- עריכת מחיר ישר מהתא (מסונכרן לערוצים).
- ResortData: דוח 12 חודשים במבט אחד — ניצול, מחויב, פנוי, לכל קבוצה או לכולן.

### מה אנשי הזמנות בודקים כל יום (מקורות תפעוליים)
תחזית: מגיעים, עוזבים, חדרים שנמכרו, מספר אורחים, התחייבויות קבוצות (שם, תאריכים, חדרים, מחיר), השוואה לתקופה קודמת; תפוסה, מחיר ממוצע ו-RevPAR מול יעד; **חגים ואירועים** ולוח "ימים מלאים".

## 2. מה כבר יש אצלנו

| נתון | מקור | מצב |
|---|---|---|
| פנויים / נמכרו / חסומים לפי סוג ולילה | `availabilityService.assessAvailability` | קיים |
| תפוסה % ללילה | `availabilityGrid` totals | קיים |
| סגור למכירה, CTA/CTD, מינ׳/מקס׳ לילות, אוברבוקינג, הקצאה | `InventoryDate` | קיים, רק stopSell מוצג |
| חסימות חדרים לתאריכים | `RoomBlock` | קיים |
| אופציות (hold / pending_payment / quote) | `Reservation.status` | קיים, לא מופרד בלוח |
| קבוצות: הקצאה, ניצול, טנטטיב/סופי, תאריך שחרור | `GroupBlock` | קיים, לא בלוח |
| מחיר BAR ללילה | `ratePricing.priceNight` | קיים, לא בלוח |
| מגיעים / עוזבים / שוהים / אנשים | הזמנות | מחושב בדוחות אחרים, לא בלוח |
| הכנסה, מחיר ממוצע | שורות חיוב / תעריף ההזמנה | לא בלוח |
| חגים | — | **חסר** (יש רק תאריכי עונה בכללי תמחור) |
| "חודש" | בורר 31 יום רצופים | **לא חודש קלנדרי** |

## 3. האפיון המוצע

### מבנה
- **חודש קלנדרי**: 1 עד סוף החודש, כותרת "נובמבר 2026", חודש קודם / הבא / היום. כל לילה עמודה; סופ"ש וחגים מודגשים בכותרת.
- **בלוק עליון — "הבית" (כל המלון)**, שורות:
  1. פנויים למכירה (גדול, צבוע)
  2. תפוסה % (סופי) · תפוסה כולל אופציות %
  3. נמכרו סופי · אופציות (hold/ממתין לתשלום)
  4. קבוצות: נוצלו/הוקצו (למשל 6/20), טנטטיב בנפרד
  5. חסומים (לא תקין / מחוץ לשירות)
  6. מגיעים · עוזבים · שוהים (חדרים)
  7. אנשים בבית (מבוגרים + ילדים)
  8. מחיר ממוצע · הכנסת חדרים
  9. מחיר BAR של הלילה
- **בלוק לכל סוג חדר** (מקופל כברירת מחדל, פותחים בלחיצה): פנויים, נמכרו, אופציות, קבוצה, חסומים, מחיר BAR, הגבלות.
- **עמודת סיכום חודש** בסוף כל שורה: סה"כ לילות-חדר שנמכרו, תפוסה ממוצעת, מחיר ממוצע, הכנסה, RevPAR.
- **בורר שורות** (כמו View Options ב-OPERA), נשמר למשתמש — לא כל אחד צריך את כל השורות.

### סימונים
- צבע תא לפי תפוסה: רגיל / >70% / >90% / מלא; "סגור למכירה" בסימון נפרד (✕) — מלא ≠ סגור.
- אוברבוקינג: אדום עם המספר.
- אייקון קטן בתא כשיש הגבלה (מינ׳ לילות, סגור להגעה/עזיבה), ריחוף מפרט.
- חג / ערב חג / אירוע: פס צבעוני בכותרת + שם בריחוף.

### פעולות מתוך הלוח
- תא פנויים → הזמנה חדשה לאותו לילה וסוג (קיים היום).
- מגיעים / עוזבים / שוהים → רשימת ההזמנות של אותו יום.
- קבוצה → מסך הקבוצה.
- חסומים → רשימת החסימות; חסימה חדשה (קיים היום).
- תאריך → הגבלות הלילה (סגירה, מינימום לילות) למי שיש לו הרשאת revenue.
- הדפסה / ייצוא לאקסל של החודש.

### מסננים
מקור (ישיר / OTA / סוכן), חברה / סוכן, תעריף — מסננים את שורות "נמכרו" ו"הכנסה" (לא את הפנויים).

### הרשאות
מחירים, הכנסה ומחיר ממוצע — רק לתפקידי הנהלה / revenue / sales / finance. קבלה רואה זמינות ותנועה.

## 4. שלבי בנייה מוצעים
1. **חודש קלנדרי + בלוק "הבית" + סוגי חדרים** עם: פנויים, תפוסה, נמכרו/אופציות, חסומים, מגיעים/עוזבים/שוהים, אנשים, סיכום חודש. (השרת: הרחבת `availabilityGrid` לחודש ולשדות הנוספים.)
2. **קבוצות, מחיר BAR, מחיר ממוצע והכנסה, הגבלות** + הרשאות על כסף.
3. **חגי ישראל ואירועים** (טבלת חגים מחושבת + אירועים ידניים), בורר שורות שמור, ייצוא / הדפסה.

## 5. החלטות פתוחות
- האם הלוח מחליף את מסך הזמינות הקיים (`/pms/availability`) או מסך נפרד. המלצה: מחליף — אותו מסך עם תצוגת חודש מלאה.
- מקור חגים: חישוב לוח עברי בקוד (ללא תלות חיצונית) או רשימה שמנהל מזין. המלצה: חישוב אוטומטי + אירועים ידניים.
