# משימה: לבנות את הפערים מהמפה (למודל הבא)

## הקשר
- **המפה:** `docs/product/gap-map.md`. נוצרת מ־`docs/product/gap-map-src/gap-map.src.md`. **עורכים רק את קובץ המקור,** ומריצים:
  `PYTHONIOENCODING=utf-8 python docs/product/gap-map-src/gen_gapmap.py docs/product/gap-map-src/gap-map.src.md docs`
  ההרצה צריכה להדפיס `broken knowledge links []`.
- **סדר הבנייה:** בסעיף "מה לבנות — סדר מוצע" בסוף המפה. עובדים לפי הסדר, פריט אחרי פריט.
- **ידע לכל מודול:** `docs/product/knowledge/NN-*.md`. **קוראים את הקובץ של המודול לפני שבונים.** הוא מסביר מה המלון צריך, מה הכללים ומה מקרי הקצה.
- **מפת הקוד:** `docs/codebase-index.md`. מחפשים בו לפי נושא, לא קוראים את כולו. כללי הפרויקט נמצאים ב־`CLAUDE.md`.

## כללים (חובה)
1. **ממשים את היכולת עד הסוף:** שרת, ולידציה, ביקורת (`auditService.audit`), ומסך באפליקציה. לא מסתפקים בשדה במודל או בכפתור שלא עושה כלום.
2. **הכסף:**
   - שורה כספית לא נמחקת ולא נערכת. כל תיקון הוא שורה חדשה, דרך `financeService`.
   - חשבוניות וקבלות מופקות רק דרך invoicer. **לא מרחיבים את `documentService` הישן.**
   - סליקה היא `mock` בלבד. כל מה שתלוי בחברת סליקה נשאר בצד.
3. **הרשאות:**
   - כל שאילתה מסוננת לפי `property`.
   - פעולה עם סיבה ומאשר: הסיבה נבחרת מרשימה, והמאשר צריך תפקיד מתאים (`requireRoles`).
4. **ממשק:**
   - בונים באפליקציה עצמה, במראה הקיים: `components/kit` ו־`kit.css`, והמראה של מסך היום (`TodayPage`). לא בונים מוקאפים.
   - טפסים ממולאים מראש מתוך ההקשר.
   - כל מסך צריך להיכנס במסך אחד ב־1440×900 בלי גלילה מיותרת.
   - כל הטקסט בעברית.
5. **בדיקה אחת לכל פריט:**
   - מריצים את חבילת ה־QA הקרובה (`npm run qa:booking | qa:stay | qa:finance | qa:frontdesk | qa:groups | ...` מתוך `server/`, עם השרת החי).
   - אם הפריט נראה במסך, פותחים אותו בדפדפן ומסתכלים עליו פעם אחת.
   - מדווחים בכנות מה נבדק ומה לא.
6. **אחרי כל פריט:**
   - מעדכנים את הסטטוס בשורות המתאימות ב־`gap-map.src.md` ומריצים את הסקריפט.
   - מוסיפים כמה שורות ל־`docs/codebase-index.md`, בסעיף שמתאים לפריט.
7. **לא מבצעים commit ולא push בלי אישור המשתמש.** אחרי כל פריט מדווחים בקצרה ומבקשים אישור.
8. **כל הדיווחים למשתמש בעברית, וקצרים:** מה נבנה, מה נבדק, מה נשאר.

### פריט 1 — מה חשוב לדעת להמשך
- **פירוט טכני:** סוף `docs/codebase-index.md`, בסעיף "Israeli-style booking & folio (2026-11-05)".
- **בדיקות:**
  - `qa:booking`: מקרים DEL / DSC / GTD.
  - `qa:finance`: מקרים NP / VCH.
  - כל הבדיקות עברו: 82/82, 51/51, ו־`qa:departures` 33/33.
- **מבנה שפריט 2 נשען עליו:**
  - חשבון של סוכן/חברה לשהייה = `Folio` עם `ownerType:'company'`, `ownerRef` = המשלם, מקושר להזמנה (`voucherService.payerFolio`). `lodgingFolio` לעולם לא בוחר חלון כזה.
  - `financeService.postCharge` עשוי לנתב חיוב לחלון המשלם (Voucher "הסוכן משלם הכול") ומחזיר `routed`. שער No Post נמצא שם (`noPostService.noPostGate`).
  - `roomCharges.planNights` מסמן לילות `toPayer`. לילה שחוצה את סכום המקדמה מתפצל (reference עם `:rest`).
- **סטטוס `deleted`:** נוסף לכל רשימות "הזמנה מתה" בשרת. **כל שאילתה חדשה שמסננת `cancelled`/`no_show` צריכה לסנן גם `deleted`.**
- **לא נבדק בדפדפן:**
  - כפתור "לא מובטחות" במסך ההגעות.
  - תיבת "ללא חיוב לחדר" בצ'ק־אין (גם לא בבדיקה אוטומטית).
  - תגית ברשימת השוהים.
  - אישור מנהל בחלון רישום חיוב.
  - לשונית "נמחקו".
  - התיבה בכרטיס החברה.
- **פערים פתוחים:**
  - שינוי הזמנה מתמחר מחדש בלי ההנחה.
  - אין מסך הגדרות ל־`Property.discountApprovalPercent` (ברירת מחדל 10) ול־`Property.nonGuaranteedReleaseTime` (18:00).
  - שינוי Voucher לא מעביר שורות שכבר נרשמו. זה מתחבר ל"העברת שורות" בפריט 2.
  - ברירת המחדל של No Post נקבעת באשף הצ'ק־אין. קריאה ישירה לשרת בלי `noPost` לא מסמנת.
  - מסגרת אשראי לבעלי כרטיס תלויה בבחירת חברת סליקה.

### פריט 2 — מה חשוב לדעת להמשך
- **פירוט טכני:** סוף `docs/codebase-index.md`, בסעיף "Folio line operations (2026-11-05)".
- **בדיקות:** `qa:finance` מקרים LOP (15 מקרים). כל הבדיקות עברו: 66/66.
- **נבדק בדפדפן:** מסך החשבון עם תיבות בחירה, סרגל הפעולות וחלון ההנחה (בלי לשמור). **לא נבדקו בדפדפן:** תצוגת שני חלונות, חלונות פיצול/העברה/איחוד/Paid Out ו"חיוב הלילה מראש" (נבדקו בשרת בלבד).
- **פערים פתוחים:**
  - העברה "מחדרים אחרים אל החדר הזה" (הכיוון ההפוך) — אין. מעבירים מהחדר המקור.
  - Paid Out: אין פתק חתימה להדפסה.
  - איחוד שורות חל רק בחשבונית דרך invoicer, לא במסלול המקומי הישן.
  - הנתיב הישן `POST /api/reservations/transfer-charges` עדיין מסמן שורות `voided` (עורך שורות). כדאי לסגור אותו או להפנות ל־`transferLines`.
  - שינוי Voucher עדיין לא מעביר שורות קיימות. אפשר עכשיו לעשות את זה ידנית בהעברה.

### פריט 3 — מה חשוב לדעת להמשך
- **פירוט טכני:** סוף `docs/codebase-index.md`, בסעיף "Foreign currency on the folio (2026-11-05)".
- **בדיקות:** `qa:finance` מקרים FX (8 מקרים). כל הבדיקות עברו: 74/74.
- **נבדק בדפדפן:** יתרה בדולרים בסיכום, חלון תשלום בדולרים (שווי, זיכוי, עודף) ובורר מטבע בחלון החיוב, בלי לשמור. מסך השערים בקופה לא נפתח בדפדפן.
- **החלטה:** החשבון נשאר בשקלים. המטבע הזר נשמר על השורה (`fx`) לתיעוד ולמשמרת.
- **פערים פתוחים:**
  - החזר לאורח במטבע זר — אין. החזר יוצא בשקלים.
  - הקבלה דרך invoicer מציגה את הסכום בשקלים בלבד, בלי פירוט המטבע.
  - אין היסטוריית שערים ושערים עתידיים (שער אחד נוכחי לכל מטבע).
  - תשלום במט"ח בכרטיס או בהעברה — אין (מזומן בלבד).

### פריט 4 — מה חשוב לדעת להמשך
- **פירוט טכני:** סוף `docs/codebase-index.md`, בסעיף "Front-desk communication (2026-11-05)".
- **בדיקות:** חבילה חדשה `npm run qa:desk` (21 מקרים), כולן עברו.
- **נבדק בדפדפן:** לשונית המרכזנית, חלון "הודעה לאורח" עם האורח ממולא מראש, וכרטיס "תקשורת קבלה" בתיק ההזמנה. **לא נבדקו בדפדפן:** לשוניות ההשכמות, Traces, היומן וספר הטלפונים, הקפצת ההתראה בצ'ק־אין/אאוט, הדפסת הודעה והתגית ברשימת השוהים (נבדקו בשרת בלבד).
- **פערים פתוחים:**
  - השכמה לכל אורח ב־Share — תלוי ב־Shares (פריט 5).
  - אין חיבור למרכזייה: השכמות ונורית הודעה ידניות.
  - נוסחי Traces קבועים בקוד, אין מסך הגדרה.
  - סגירת היום עדיין לא בודקת השכמות של מחר.
  - עריכת הודעה שנשלחה לכמה אורחים — אין (הודעה נרשמת לאורח אחד).
