# חיבור למערכת invoicer העצמאית

> **החלטת בעל המוצר (19.10.2026): כל החשבוניות, הקבלות ומסמכי הזיכוי מופקים במערכת החשבוניות שלנו — נפרדת לחלוטין מ־Hotel4u — ורק דרך ה־API שלה.** Hotel4u שולח אירועי חיוב ומציג את התוצאה; הוא לא מפיק מסמך פיסקלי בעצמו. מנגנון המסמכים הפנימי (documentService, הקצאות רשות המסים, מבנה אחיד, מנוע החשבונאות) הוא מורשת — לא מרחיבים אותו.

המערכת החדשה נמצאת ב־`../invoicer` ומופעלת בנפרד. אין שיתוף מודלים, מסד נתונים או אימות משתמשי מלון. מנוע החשבונאות הקודם נשאר זמין; לא הועברו מסמכים היסטוריים ולא הופעל חיבור בפועל.

## הגדרה בשרת Hotel4u

```env
INVOICER_API_URL=http://127.0.0.1:4310
INVOICER_API_KEY=<server-only key created in invoicer for sourceSystem hotel4u>
```

בפריסה מרוחקת יש להשתמש ב־HTTPS. המפתח נשמר בשרת בלבד.

1. יוצרים מפתח גישה ב־invoicer עם מזהה מערכת מקור `hotel4u` והרשאות קריאה וכתיבה.
2. מנהל רשת או מנהל כספים מחבר נכס: `POST /api/pms/invoicer/connect`, כולל `propertyId` ופרטי זהות משפטית חסרים.
3. בודקים `GET /api/pms/invoicer/status?propertyId=...` ו־`GET /api/pms/invoicer/overview?propertyId=...`.
4. רק אירועים חדשים שנוצרו לאחר הגדרת החיבור מקבלים משימת outbox בנושא `integration.invoicer`. מתאם השרת שולח אותם באופן חוזר עם אותו מזהה אירוע. משימות שנכשלו נשארות מתועדות להתאוששות.
5. עיבוד התור הקיים דרך `POST /api/pms/accounting/recovery/run` נשאר תחת הרשאות הנכס הקיימות.

אירועים מיובאים נשמרים ב־invoicer לבחינה ומיפוי. הם אינם מפיקים מסמך או הכנסה נוספת אוטומטית. הפקת מסמכי TEST מתבצעת בממשק העצמאי; הפקה חיה, סליקה, חתימה, דיווח ומיגרציה היסטורית טרם הופעלו.
