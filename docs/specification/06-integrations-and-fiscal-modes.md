# חיבורים ושני מסלולים חשבונאיים

## הכרעת בעל המוצר

שני המסלולים מאופיינים. פרופיל חשבונאי נבחר לכל ישות, לא לכל עובד. אסור להפעיל שני מנפיקים מתחרים לאותו סוג מסמך ואותה סדרה. מעבר מסלול הוא תהליך מיגרציה מאושר עם cutover וסגירת פעולות ממתינות.

| נושא | הנפקה עצמית | מנפיק חיצוני |
|---|---|---|
| מספור ומסמך מקור | מנוע פיסקלי של הפלטפורמה, לאחר אישורי תחולה | הספק; PMS שומר מזהה, מספר, עותק סופי וסטטוס |
| חשבוניות ישראל | חיבור מורשה והרשאות לרשות המסים | הספק מבקש ומחזיר סטטוס ומספר; PMS אינו ממציא |
| חתימה ומסירה | נדרש מפרט עדכני, חתימה, הסכמה וארכיון | הספק לפי חוזה; PMS מציג ראיות והסכמה ומוודא מסירה |
| תיקון מסמך | מסמך נגדי עם קישור למקור | פקודת תיקון לספק וקבלת מסמך סופי |
| קובץ אחיד | מנוע יצוא לפי תחולה וסימולטור | חוזה מסירת קבצים; בירור אם פעילות PMS עדיין מחייבת יצוא משלה |
| תקלת ספק | לא מנפיקים בלי כלל מס/חתימה/הרשאה תקפים | pending, בירור לפי מזהה; אין PDF מקומי שמוצג כחשבונית |
| רישום תוכנה | בירור חובת רישום לפי פונקציות ותפוצה | עצם השימוש בספק אינו מוכיח פטור אם PMS מנהל ספרים |
| אחריות | חברת התוכנה והמפעיל לפי חובה וחוזה | אין העברת אחריות מלאה רק משום שיש API |

ראו [שירות רישום תוכנה](https://www.gov.il/he/service/registration-software-designed-managing-computerized-accounting-system), [מבנה קובץ אחיד](https://www.gov.il/BlobFolder/service/registration-software-designed-managing-computerized-accounting-system/he/Service_Pages_Income_tax_horaot-131.pdf) ו[חוזר מסמכים ממוחשבים](https://www.gov.il/blobfolder/generalpage/-software-houses-digital-documents/he/incometax_incometaxsoftwarehousesinfo_hoz24-2004.pdf). החוזר היסטורי; אין לראות בו לבדו אישור מסלול עדכני.

## רצף הנפקה

FIN-01 → FIN-06: בוחרים חיובים, סוג מסמך, ישות, משלם, מטבע ומועד לפי כלל מס. מוצגת תצוגה ללא מספר סופי. מאמתים מקור חיובים, סכומים, מס, לקוח ומספר הקצאה כשחל. שליחה יוצרת operationId ונועלת גרסת בקשה. מצבים: draft → validated → submitted → issued או rejected או unknown. issued מחייב documentId, מספר וסדרה, סכומים סופיים, סטטוס הקצאה, קובץ מקור וחותמת זמן. unknown דורש lookup לפני retry. מסמך שהונפק אינו נערך; FIN-07 מנפיק תיקון מקושר. קבלה קשורה לתקבול, חשבונית לחיוב לפי הדין; לא מפיקים אחת במקום השנייה רק כי מסך checkout צריך להיסגר.

## חוזה חיבור מינימלי

כל ספק: providerId, version, organization/property/entity scope, authentication בעלת תוקף, sandbox, operationId, externalId, timeout, retry policy, webhook verification, rate limits, timezone/currency, schema version, owner ותאריך ביקורת. בקשה ותשובה מצומצמות נשמרות בלי סוד או מידע מיותר. חתימה/אימות הודעות אינו מתחלף בהסתמכות על כתובת IP בלבד. כל ניסיון חוזר נשאר באותה פעולה עד כשל ודאי.

| חיבור | פקודות ונתונים | מקור אמת | התאוששות ובדיקה |
|---|---|---|---|
| OTA/channel | הזמנות, שינוי, ביטול, מלאי, תעריפים והגבלות | ספק לאישור חיצוני; PMS לזמינות | dedupe, סדר גרסאות, פיוס snapshot, overbooking לטיפול |
| סליקה | authorization, capture, void, refund, settlement | סולק | lookup, webhook מאומת, פיוס, כפל ודאות ולא retry עיוור |
| fiscal | issue, credit, allocation, final file, exports | מנפיק | correlation, lookup, סדרות, אין שתי חשבוניות לאותה בקשה |
| מנעולים | הנפקה, הארכה, ביטול, מפתח נוסף | PMS לטווח; ספק למפתח | תוצאה לכל מפתח; fallback תפעולי מתועד, לא מצב כניסה מזויף |
| POS | חיוב/תיקון, קוד שירות, אישור אורח/חשבון | POS לצריכה; PMS לחשבון | מזהה פריט חיצוני, duplicate, מס שונה, חדר שהחליף אורח |
| הודעות | templateVersion, recipient, consent, delivery | מערכת המקור לתוכן; ספק למסירה | delivered/bounced/pending, opt-out לפי תכלית, ללא מידע רגיש בהודעת SMS |
| הנהלת חשבונות/בנק | ייצוא תנועות, חייבים, שערים ופיוס | ספק לספר הראשי/בנק לבנק | period lock, סכומים, מיפוי ישות, לא שכתוב רטרואקטיבי |
| משאבי אנוש | עובד, משמרת ונוכחות | ספק HR | פרטי עובד מצומצמים; אין מנוע שכר בישראל במסך ממשק |
| רשות ציבורית | קובץ/בקשה, אישור קליטה ואישור הגשה | הרשות | רק API מוסמך; פתיחת פורטל או יצירת קובץ אינן הוכחת הגשה |

## קריטריונים לבחירת ספק

נדרשות ראיות sandbox לכל פעולה, מדיניות retention ויציאה, הסכם עיבוד מידע, כתובות אחסון ותתי־מעבדים, SLA, עלות פעולה, זכויות export ותיעוד שינוי schema. נבדקים ביטול/החזר חלקי, unknown, webhook כפול ומאוחר, סדר גרסאות, שינוי מפתח וסיום חוזה. אין לאשר ספק על בסיס דף שיווק. תקנה 15 נבדקת לפי [מדריך הרשות להתקשרות חיצונית](https://www.gov.il/BlobFolder/reports/election-2023-accessible/he/elections_2023_portal_Information%20security%20guide%20for%20contracting%20with%20an%20external%20party.pdf); המדריך פורסם בהקשר בחירות ולא מחליף ניתוח חוזה המלון.
